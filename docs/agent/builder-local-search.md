# Builder bundled retrieval — release-only map

Decision: local map/engine inside plugin, updated ONLY by plugin releases. No
remote HTTP/MCP search, downloader, local updater, separate backend or fallback.

## Source / rights / reproducibility

- CodeGen-X UI8Kit commit `6b2e71b56375cf3aab161a755c8eee806e7309fb`.
- Root MIT license permits redistribution with copyright/license notice. Copied
  engine has no package-specific restrictive license; `private:true` is npm
  publishing metadata. No private datasets, runtime templates or credentials copied.
- Unmodified TS + license + source SHA256 lock: `tools/vendor/facet-search/`.
- Original Stock index: `worker/catalog/stock.v0.json`, version0, 673108 bytes,
  digest `sha256:a9d256e6935c6a8d579f86d634eebb46dfe36cacd02d9e4e2a0fdce4ff41664a`.
- Bun1.4.4 transpiles offline to standalone ESM. The runtime manifest locks source
  provenance, schema, version, counts, license and each artifact hash. CI checks
  generated bytes plus upstream canonical JSON digest. No timestamp/randomness.
- Official site packaging recursively includes the worker/catalog resources;
  no runtime import depends on tools/vendor, the Stock checkout or npm packages.
  Copied-resource test runs from a temporary independent folder without npm.

## Boundary / checklist

- Pure pinned engine → small Node catalog adapter → SDK custom tools. WordPress
  sends authoritative installed definitions + actual catalog runtime server-side.
- `search_catalog`: default5/max10 cards, scoped BEFORE ranking/collapse; ids,
  title/description, relevant variant, labels and draft status, never full schemas.
- `get_block_details`: one exact block/variant schema/default/data-record set;
  mandatory before changed proposals, maximum48KB. Stock metadata is untrusted
  data, not instructions. PHP draft normalization/schema validation is unchanged.
- Case preserved (`twoActions` != `twoactions`); no registry/organism alias guesses.
  Current map excludes50 unavailable Stock variants and80 screens. All482 installed
  variants match. Only actual latte/twig targets; unmapped sources are explicit.
- Bounded schema/inputs/depth/size, own-property checks and forbidden prototype keys.
  No regex supplied by callers, arbitrary path, shell, URL, source installation,
  network search, provider replacement, keys or automatic publish.
- Map failure returns a safe diagnostic through IPC/WP; no silent huge fallback.
- Tool progress allowlist covers new tools, retaining the old name for old history.
  Telemetry, restrictive sandbox, revision-aware preview and idempotency preserved.
- Module cache contains only immutable public index; installed scope/detail-inspection
  state is per run. Worker SQLite still isolates site/page/request and replay.
- NON-LIVE tests: Stock behavior parity, all applicable vocabulary incl soft values
  with no installed labels, multilingual labels/synonyms, input/size/prototype errors,
  target/source/case/variant exclusion, corrupt resource, selected schema/proposal,
  copied packaged resources, existing auth/replay/usage and real local WP HTTP fixture.

## Reproducible local measurement (not billing / live latency)

`node tools/builder/local-search-bench.mjs`, Linux x64 Node24.22.1, 1000 warmed
queries after50 warmups, `job=hero`, limit5. One run: cold load+scope82.046ms,
median0.076ms/p950.168ms; 3 cards /2142 response bytes; descriptor7444 bytes.
Observed heap delta13275496 bytes, RSS delta36089856 bytes, whole-process peak
RSS100792KiB; CPU user320.807ms/system12.312ms includes load+all benchmark queries.
These are local process observations, not guarantees, per-query CPU estimates,
model tokens/costs or the owner's ~45-second live turn. Repeat script for new data.

## Remaining acceptance / deployment

No paid turn, model API, vault access, owner machine, VPS or browser action used.
Search path tested through own WP with explicitly injected NON-LIVE runner only;
no claim of new live SDK/tool selection or Windows acceptance. Updating the plugin
alone will NOT update local-wp's separately pinned worker resource; next resource
release must include the entire worker/catalog tree and current worker adapter.
No ZIP delivery or standalone updater is part of this change.
