# ADR-001 — Engine-agnostic architecture, post-type modules, performance, skins

Status: **accepted** (decisions by the project owner, 2026-10-16). Implementation status per item below.

## 0. Context — audit of the current state (commit 4895c4d, 2026-10-16)
- DI container exists only in the parent: `themes/latte/classes/Core/{Application,Container}.php`, services in
  `themes/latte/configs/services.php`. Child themes do not use it.
- Children are inconsistent: `latte-press` = tokens + one view; `latte-folio` = procedural `inc/projects.php`;
  `latte-shop` = six procedural `inc/*.php` files with their own namespace style.
- CPT code is copy-pasted between folio (`project`) and shop (`product`, `shop_order`): register_post_type,
  metabox, nonce, save_post sanitization, `register_post_meta`, `pre_get_posts` — the same ~150 lines twice.
- `latte-shop/inc/catalog.php` hardcodes `post_type === 'product'` (purchasable is not a capability).
- Engine coupling: `ThemeService` talks to `LatteEngine` directly; views are `.latte` files with extension in names.
- Theme Check baseline: see `wporg-theme-review.md`.

## 1. Timber-style layering
```
WP query → Context builders (PHP, engine-agnostic, return plain data, NO escaping)
         → Renderer interface (render(view, context): string)
             ├─ LatteRenderer  (default)
             └─ TwigRenderer   (optional, needs twig/twig)
         → views (thin) → UI8Kit primitives (Latte + Twig variants generated by ui8kit/codegen, identical DOM)
```
- Renderer chosen via DI; filter **`wpfasty_renderer`** (`'latte'|'twig'` or a `RendererInterface` instance).
- View names have **no extension** (`pages/single`); each renderer appends its own (`.latte` / `.html.twig`).
- One root chain for both engines: child views → parent views → primitives (`wpfasty_latte_roots` stays as alias,
  new `wpfasty_view_roots`).
- Escaping happens **in templates** (auto-escape in both engines), never in context builders. Exception: values that are
  already HTML (post content, `wp_kses_post` archive description) are marked as HTML in the context and printed raw.

## 2. Thin views — common subset (must translate 1:1 between Latte and Twig)
Allowed: include/embed with params, block, if/else, for, variable print, filters `esc_url`, `kses`, `icon`, `t` (i18n).
Not allowed in views: PHP function calls, queries, `|noescape` on context data except HTML-marked fields.
Slots = `embed` (Latte `{embed}` / Twig `{% embed %}`).

## 3. Declarative post-type modules
A child theme (or a companion plugin) drops `types/<name>.php` returning an array:
```php
return [
  'name' => 'project', 'args' => [...register_post_type args...],
  'taxonomies' => ['project_type' => [...args...]],
  'fields' => ['client' => ['type'=>'string','label'=>'Client','sanitize'=>'sanitize_text_field'], ...],
  'views' => ['single' => 'pages/project', 'archive' => 'pages/work', 'card' => 'blocks/project-card'],
  'context' => fn(array $post): array => [...],
  'supports' => ['purchasable' => ['price_field' => 'price']],
  'archive' => ['per_page' => 9],
];
```
The parent (`WPFasty\Types\Registry`, DI service `types.registry`, filter `wpfasty_type_dirs`) auto-registers:
CPT + taxonomies, `register_post_meta` (prefixed `_<prefix>_<field>`, typed, sanitized, `show_in_rest`),
metabox with nonce + capability check, save handler, view routing (`wpfasty_resolve_view`), `pre_get_posts` per_page,
post data enrichment (`wpfasty_post_data`) and capability lookups (`wpfasty_type_supports($type, 'purchasable')`).

### 3a. Conflict with wordpress.org (recorded, needs owner decision later)
wp.org forbids CPTs/taxonomies/non-design metaboxes in themes (Required rules, "Plugin territory").
Implemented split (2026-10-16): the theme keeps `WPFasty\Types\Registry` for *presentation only* (module loading,
view routing, archive query/title, post view-models, capability lookup). Data registration — `register_post_type`,
`register_taxonomy`, `register_post_meta`, metabox + nonce + save, admin columns — is in the companion plugin
`plugins/wpfasty-types` (hooks `wpfasty_types_loaded`). Theme Check: 0 REQUIRED for all four themes after the split.
Folio/shop need the plugin active (admin notice otherwise). Open question for the owner: whether the generator
should always emit the plugin, or inline it for non-wp.org builds.

## 4. Performance
- The main query is the content query (no secondary WP_Query for the same list); `pre_get_posts` adjusts it.
- Batch: `update_meta_cache` / `update_object_term_cache` (WP_Query does this for the main query) **plus**
  `update_post_thumbnail_cache()` for featured images — no N+1. Guard: `tools/perf/queries.php` (SAVEQUERIES,
  query count for 2 vs N posts must be equal).
- Lazy context: a view declares the parts it needs (e.g. comments only for singular with comments open).
- Conditional loading: admin code (metaboxes) only on `is_admin()`.
- Compiled template cache (`~cache/`, excluded from zips). Per-page CSS possible later.

## 5. Skins
Parent `:root` / `.dark` tokens (`themes/latte/assets/css/tokens.css`) → child `tokens.css` override →
optional Customizer token block (**postponed**). Token names stay shadcn-compatible.
