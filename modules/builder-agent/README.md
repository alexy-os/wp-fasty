# Builder Agent — optional ModulY module

Manual `wpfasty-builder` works without this module, ModulY, Node or a provider.
This directory owns the Agent PHP adapters, separately built UI and Node resource.
Install a publisher-trusted signed module through the existing ModulY module UI;
installation is separate from explicit enablement. No automatic activation here.
Disabling preserves all page drafts/history and active/draft policy versions.

Requires active Builder PageOperations API 1 and Node 24 resource advertising
`wpfasty-agent/1`, `local-search/1`, `policy/1`, `diagnostics/1`. No model call is required for status.
The old local-wp resource pinned to 873b00d is intentionally rejected by Agent PHP;
manual editing remains available. A future authorized manager release must refresh
its pinned worker path/full resource list. `resource.json` is not an installer.

Build both UI bundles with the pinned toolchain:
`bun run --cwd plugins/wpfasty-builder/editor build` from the repository root.
For a developer-only fixture, stage changed source, set `WPFB_MODULY_RUNTIME` to
an audited published ModulY plugin and run `bun tools/builder/pack-agent.ts`.
That output is UNSIGNED, only usable in the explicit isolated development-mode
CLI fixtures. Do not enable unsigned packages in production or treat it as a
publisher-signed release. No signing keys are read/generated by this build.

[Architecture, test matrix and coordinated rollout](../../docs/agent/adr-003-optional-builder-agent.md).
Search is local/offline; the actual Agent model transport still uses its provider
when explicitly requested. All tests in this change use NON-LIVE injected runners.

## Coordinated signed release (t220)

The first publisher release remains version 0.1.0 (there was no previous signed
Agent release). Production signing runs only in the phpfasty/wpmodules protected
GitHub Actions context with its existing MODULY_SIGNING_KEY and verifies against
the existing embedded phpfasty public key. Never copy that key to this repository.
The manager must pin this complete worker tree, including the worker LICENSE,
local catalog, engine and policy resources. Windows/Linux native no-model checks
are not proof of a live model turn or owner-machine GUI acceptance.
